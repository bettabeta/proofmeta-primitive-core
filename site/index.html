03 / WHAT PROOFMETA IS

A protocol primitive for digital artefacts — not a platform.

ProofMeta is an open specification for wrapping digital artefacts in machine-readable permission metadata. Skills are the first use case — not the category. The same primitive applies to datasets, APIs, code, documents, media, model outputs and agent capabilities.

The license is a pointer, not a contract. It references terms, scopes and proof — it does not replace counsel. ProofMeta does not replace legal agreements. It makes permission computable.

Open. Neutral. No lock-in. No marketplace dependency. No platform capture. Builder-native infrastructure — not a storefront.

04 / HOW THE LIFECYCLE WORKS

Discover. Request. Decide. Act with proof.

An agent or app discovers permission metadata attached to an artefact, requests access, receives a machine-readable grant or denial, and acts only inside the terms — with an auditable trail.

// Permission metadata — pointer to terms, not the contract itself
{
  "artefact":   "urn:proofmeta:skill:onboarding-flow",
  "scope":      ["execute", "derivative-allowed", "training-excluded"],
  "terms_url":  "https://example.com/terms/onboarding-flow",
  "terms_hash": "sha256:a1b2c3...",
  "proof":      { "envelope_id": "env_...", "status": "GRANTED" }
}
OPEN → PENDING → GRANTED | DENIED → REVOKED

Every state is machine-readable. Every transition is auditable. Revocation is expressible — not implied.

"Is this only about monetizing skills?"

No. Skills are the first visible use case because they are already agent-consumed at scale. ProofMeta is a permission primitive for any digital artefact — free, paid, or internal.

"Does this replace my lawyer?"

No. ProofMeta makes permission computable for agents and apps. Legal agreements still exist — the protocol gives machines something parseable to point at.

"Which runtimes can use this?"

Any runtime that can fetch JSON or YAML and verify signatures. SDKs are convenience — not a lock-in layer.
